# KnowledgeWalk — 초기 분류와 제작 방향

기준일: 2026-10-27 (한국 시간). 사용자 제공 WordPress 메뉴 스크린샷 8장을 기준으로 기록했다. 현재 운영 사이트를 직접 조사한 결과가 아니다.

## 프로젝트 범위

- 작업 저장소는 `linguawalk/Knowledge-Walk` 하나로 제한한다.
- 도메인은 `knowledgewalk.net`이다. 현재 WordPress 운영 사이트는 새 사이트 검증과 사용자 승인 전까지 변경하지 않는다.
- 새 사이트는 WordPress에 의존하지 않는다. 기존 메뉴는 초기 콘텐츠 분류로 활용한다.
- 중요한 삭제, 운영 사이트 배포, 도메인 전환은 사전에 확인한다.
- 이번 기록은 사이트 구현이나 자동화 가동, 업로드, 배포를 의미하지 않는다.

## 콘텐츠 성격

백과사전식 항목이나 개념 연결망보다, 한 소재를 중심으로 독립적으로 즐기는 짧은 이야기다. 사용자에게 승인받은 「베네치아에서는 사자에게도 날개가 있다」를 문체·길이·독자 난이도의 기준으로 삼는다. 해당 기준 원고의 출처 검증은 별도 미완료 상태이므로, 문체 승인과 게시 준비 완료를 혼동하지 않는다.

- 본문 약 2,000자 안팎을 기본으로 하되 소재에 맞춰 조절한다.
- 어렵거나 유치하지 않은 친근한 한국어를 사용한다.
- 구체적인 사물, 장소, 이름, 풍습, 발견 등의 궁금증에서 시작한다.
- 철학적 교훈이나 국가·권력 해석으로 매번 확대하지 않는다.
- 각 글에는 하나의 대분류와 하나의 세부 분류를 부여한다. 여러 지면에 같은 글을 중복 배치하거나 같은 소재를 분야별로 반복 제작하지 않는다.
- 사실·전설·해석을 구분하고, 출처를 확인한 뒤 공개한다. 확인되지 않은 대화·심리·장면은 만들어내지 않는다.
- 글과 어울리는 이미지를 함께 준비한다. 실제 사진은 출처와 이용 조건을 확인하고, AI 삽화는 설명용 그림임을 표시한다. AI 그림을 특정 유적의 실제 모습처럼 소개하지 않는다.
- 사용자는 콘텐츠 기획·편집 방향과 중요한 디자인 선택에 집중한다. 기술 선택과 구현은 AI가 담당한다.

## 초기 분류: 8개 대분류 / 43개 세부 분류

사용자 스크린샷의 표기와 순서를 그대로 옮겼다. `History > America`와 `Cities > Americas`는 현재 서로 다른 표기 그대로 보존한다. `Folks`, `Artificial-Intelligence`, `Earth-Science`도 임의로 고치지 않는다. 콘텐츠가 쌓이면 사용자와 함께 조정한다.

| 대분류 | 세부 분류 |
|---|---|
| History | Korea, Asia, Europe, America, Middle East, Africa |
| Cities | Asia, Europe, Americas, Middle East, Africa |
| Culture | Architecture, Literature, Philosophy, Music, Art, Film, Sports |
| Life | Folks, Clothing, Food, Housing |
| Companies | Technology, Automotive, Finance, Media, Fashion |
| Computing | Computers, Software, Internet, Programming, Artificial-Intelligence |
| Finance | Money, Banking, Insurance, Investment, Fintech |
| Science | Mathematics, Physics, Chemistry, Biology, Earth-Science, Engineering |

예시: 베네치아 사자 이야기는 `Cities > Europe`에 속한다. 초기 분류에 모든 소재를 억지로 채우기 위해 글을 만들지 않는다.

분류가 바뀌어도 기존 글과 주소를 최대한 유지하도록 설계한다. 분류 이름과 글의 고유 식별자를 분리하고, 분류 위치 이동만으로 독자가 저장한 글 주소가 깨지지 않게 한다. 아직 구체적인 주소 체계와 구현 방식은 확정하지 않았다.

## 사이트형 제작의 의미

사이트는 날짜순 글 나열을 중심에 놓기보다, 첫 화면에서 추천 이야기와 8개 분야의 콘텐츠를 골라 읽고, 각 세부 분류에서 이미지·제목·짧은 소개를 탐색하는 방식으로 설계한다. 각 이야기에는 독립적인 읽기 페이지가 있다. 모든 카테고리 페이지를 사람이 따로 작성하는 대신 콘텐츠 정보에 따라 자동 구성하는 방향이다.

자동화는 두 가지로 구분한다.

1. 콘텐츠 제작: 소재 후보 선정 → 출처 조사 → 초안 → 이미지 준비 → 사실 확인·편집 검토.
2. 사이트 구성: 공개 승인을 받은 콘텐츠 → 이야기 페이지·분류별 목록·첫 화면의 갱신.

초안 파일이 저장되거나 GitHub에 업로드되었다는 이유만으로 운영 사이트에 공개하지 않는다. 현재 검토용 브랜치의 업로드도 사이트 게시 승인이 아니다.

## 추후 논의할 사항

- 콘텐츠 제작 주기와 한 번에 만드는 수량.
- 분야별 제작 비중과 첫 제작 묶음.
- 검토 방식, 공개 승인 방식, 예약 게시 여부.
- 운영 사이트의 업데이트 시점과 실제 배포 절차.
- 정기 생성 작업의 실행 환경, 필요한 서비스와 비용.

상시 자동 생성은 이 채팅이 스스로 수행하는 기능이 아니다. 별도의 실행 장치를 구현해야 하며, 현재 예약 작업이나 자동 게시를 설정하지 않았다.

## 다음 작업 제안

첫 화면·세부 분류 목록·글 상세 화면과 검색의 정적 사이트 구현을 진행했다. `config/categories.json`이 초기 분류를 보관하고, `content/stories/`의 원고에서 HTML을 생성한다. 사용자는 `index.html` 기반 접근과 자동 구성을 승인했다. 구현·실행·검증 방법은 루트 `README.md`를 따른다.

기준 원고는 출처 검증이 끝나지 않아 검토용 빌드에만 표시한다. 공개 배포, 도메인 전환, 정기 콘텐츠 제작과 게시 일정은 별도 결정한다. 다음 단계는 화면 검토와 출처 확인, 이후 다른 분야 시범 원고 제작이다.
