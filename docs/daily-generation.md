# 매일 아침 이야기 제작과 사용자 검토

## 현재 상태

새 이야기 10편을 게시해 운영 홈페이지에는 총 28편이 있습니다. [최근 10편 읽기](https://knowledgewalk.net/collections/20261027-ten-everyday/index.html).

**매일 오전 9시(한국 시간)에 초안 30편과 설명용 삽화를 만드는 설정과 코드를 준비했습니다. 아직 유료 AI 연결이 확인되지 않아 자동 작성은 꺼져 있습니다.** 설정 검사는 글을 생성한 것과 다릅니다. 실제 API를 이용한 제작 성공이나 하루 30편 가동을 아직 확인했다고 말하지 않습니다.

현재 Codex 환경에는 `OPENAI_API_KEY`가 없으며, 연결된 GitHub 인증은 저장소 비밀키 목록 조회·추가를 허용하지 않습니다. GitHub 작업의 무과금 설정 검사도 성공했고, 별도 진단 단계에서 그곳에도 AI 키가 없음을 확인했습니다. 유료 생성 단계는 건너뛰었으며 실제 자동 생성 수는 0편입니다. [확인 기록](../config/automation-status.json)을 따릅니다. 채팅에 키나 비밀번호를 보내지 않습니다.

## 앞으로의 제작 순서

1. **오전 9시 제작 시작:** 빈 소주제와 원고가 적은 분야부터 소재 후보를 고릅니다. 기존 제목·질문과 비교해 같은 이야기를 반복하지 않도록 살핍니다.
2. **조사와 초안:** 공식 기관·박물관·기업 연혁 등 지정 출처를 실제 웹 검색합니다. 근거 URL이 검색 결과에 없거나 허용한 출처가 아니면 완성 원고로 받지 않습니다.
3. **별도의 AI 감수와 이미지:** 다른 요청으로 핵심 주장·근거를 다시 살피고, 통과한 원고에 AI 설명용 삽화를 만듭니다. 약 3분 분량의 한국어 이야기로 정리합니다.
4. **아침 검토함에 보관:** 분야/소주제 폴더에 저장하고 날짜별 목록을 만듭니다. 본문·이미지·출처 후보와 확인 상태를 함께 봅니다.
5. **사용자 확인 후 게시:** 사용자가 이 채팅에서 특정 글이나 날짜 묶음의 게시를 요청하면 AI가 출처 대조·수정을 마무리하고 승인 기록을 남겨 홈페이지에 반영합니다. 선택하지 않은 글은 검토함에 둡니다.

자동 수집과 AI 감수는 독립적인 원문 대조나 사용자의 승인과 같지 않습니다. 자동 원고의 `source_review`는 `pending`, `status`는 `draft`, `publication_ready`는 `false`로 잠그고 승인 정보는 비워 둡니다. AI가 출력에 승인 값을 넣어도 코드가 채택하지 않습니다. 근거 후보는 ‘확인 완료’ 자료와 구분해 표시합니다.

목표는 매일 30편입니다. 자료나 이미지 생성에 문제가 있으면 일부 결과와 실패 내역을 보존하며, 12편만 완료했다면 30편 완료라고 표시하지 않습니다. 나머지를 억지로 채우거나 검증을 생략하지 않습니다.

## 매일 확인할 곳

[고정 아침 검토함](https://github.com/linguawalk/Knowledge-Walk/blob/drafts/review-queue/docs/review/daily-queue.md)

같은 주소에서 날짜를 고르면 그날의 글을 읽게 구성했습니다. GitHub의 `drafts/review-queue` 브랜치에 쌓이며 날짜마다 브랜치를 새로 찾을 필요가 없습니다. 일반 독자가 보는 홈페이지에는 승인한 글만 들어갑니다. 저장소가 공개되어 있으므로 GitHub 검토함은 비공개 공간은 아닙니다.

이 채팅에 매일 자동 메시지를 보내는 기능은 설정하지 않았습니다. 사용자가 이 채팅에서 검토·수정·게시를 이어갈 수 있습니다.

## 유료 AI 연결: 사용자에게 필요한 한 번의 설정

ChatGPT 구독과 자동 제작용 API 사용료는 별도입니다. 글 30편, 출처 검색, 독립 AI 감수, 이미지 30장의 비용이 발생할 수 있습니다. 아직 실서비스 호출을 하지 않아 실제 한 편 사용량과 월 비용을 단정하지 않습니다. 연결 후 작은 유료 시험으로 사용량과 모델 권한을 확인하고, 그 결과를 기준으로 가동 조건을 확정합니다.

API를 처음 쓰는 경우:

1. [OpenAI API 서비스](https://platform.openai.com/)에서 사용할 프로젝트와 결제·사용량 설정을 준비합니다.
2. 프로젝트용 API 키를 발급합니다.
3. [Knowledge-Walk의 GitHub 비밀키 설정](https://github.com/linguawalk/Knowledge-Walk/settings/secrets/actions)에서 **New repository secret**을 선택합니다.
4. 이름은 `OPENAI_API_KEY`, 값에는 발급한 키를 넣어 저장합니다. 키는 채팅·원고·저장소 파일에 넣지 않습니다.
5. 이 채팅에는 키를 공개하지 않고 “AI 연결 키를 저장했습니다”라고 알려 줍니다. AI가 연결 상태를 확인하고 가동 플래그를 켭니다. 이미 요청받은 9시·30편 조건에 대해 다시 허락을 요구하지 않습니다.

Codex 환경의 비밀키와 GitHub Actions의 비밀키는 서로 다른 보관 위치입니다. 이 자동화는 GitHub에서 실행하므로 위 저장소의 Actions 비밀키가 필요합니다. API 키가 있어도 이미지 모델 권한이나 결제 상태가 다를 수 있어 실제 연결 시험을 별도로 확인합니다.

## 시간과 실행 한도

- 시간 기준은 `Asia/Seoul`입니다. GitHub 예약식 `0 0 * * *`는 한국 시간 오전 9시입니다.
- **9시에 제작을 시작하도록 요청하는 설정**이며 30편이 9시에 모두 완성되는 것은 아닙니다. GitHub 대기열에 따라 시작이 늦어질 수 있습니다.
- 하루 완성 목표는 30편, 소재 예비 후보는 10개입니다. 요청 수 128회, 이미지 요청 36회, 연속 실패 5회 등의 상한을 둡니다. 재시도도 요청 수에 포함합니다.
- 이 상한은 프로그램의 요청 수를 제한하며 금액 단위의 과금 차단을 보증하지 않습니다. 실제 모델 요금과 계정 사용량 조건을 확인합니다.
- 같은 날짜를 다시 실행하면 저장된 완료 원고를 재생성하지 않습니다. 한 편을 마칠 때마다 검토 브랜치에 체크포인트를 올리고, 실패 내역도 저장한 뒤 다음 요청을 진행합니다. 원격 저장이 실패하면 추가 유료 요청을 중단합니다. 이미지에서 실패한 원고는 저장된 조사·본문을 재사용합니다. 외부 API 호출 직후의 강제 종료처럼 원격 저장 전 중단된 요청까지 중복 과금이 전혀 없다고 보증하지는 않습니다.

## 기술 구성과 검증 범위

- [예약 작업](../.github/workflows/daily-drafts.yml): 정기 실행과 수동 설정 검사. 자동화 관련 코드를 main에 올렸을 때는 유료 호출 없이 설정만 검사합니다.
- [가동 설정](../config/daily-generation.json): 현재 `enabled: false`입니다. 활성화 여부와 비용 연결을 분명히 구분합니다.
- [편집 원칙](../config/prompts/daily-editor.md): 문체, 독립 소재, 근거, 전승·추정 구분과 AI 삽화 원칙.
- [실행기](../tools/daily_generation.py): OpenAI Responses의 웹 검색과 구조화 출력, 별도 감수 요청, 이미지 생성과 압축, 날짜별 중복·상태 관리.
- `content/generation_runs/YYYY-MM-DD.json`: 실제 완료 수, 요청 횟수, 중단·실패 내역. 이 파일에는 API 키를 저장하지 않습니다.
- `docs/research/daily/YYYY-MM-DD/`: 검색·감수 응답 식별자, 후보 URL과 짧은 근거, 이미지 해시. 원문 전체를 복제하지 않습니다.

예약 작업은 처음부터 끝까지 이 저장소에만 접근하며, 유료 요청 전 검토 브랜치 쓰기 권한을 확인합니다. `main`으로 병합하거나 웹사이트를 게시하는 단계가 없습니다. 자동 글·이미지는 영구 검토 브랜치에만 커밋합니다.

실서비스 API 연결 전에는 실제 모델 결과·요금·30편 처리 시간을 확인할 수 없습니다. 오프라인 검사에서는 게시 승인 차단, 검색에 없는 URL·허용하지 않은 출처 거부, 요청 상한, 같은 날짜 재실행, 이미지 실패 후 재개, 중단 복구와 비밀키 누출 방지를 확인합니다. 모의 결과를 실제로 작성한 인문학 콘텐츠나 일일 가동 성공으로 세지 않습니다.

API 요청 형식은 실제 열람한 OpenAI 공식 SDK의 [Responses 요청 정의](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response_create_params.py), [웹 검색 정의](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/web_search_tool_param.py), [이미지 요청 정의](https://github.com/openai/openai-python/blob/main/src/openai/types/image_generate_params.py)를 근거로 준비했습니다. 이미지 압축에만 고정 버전 Pillow를 사용합니다. 기본 사이트 빌드는 계속 Python 표준 라이브러리만 사용합니다.
