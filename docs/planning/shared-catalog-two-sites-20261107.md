# 국가별·분야별 공통 콘텐츠 운영안

2026-11-07 사용자 적용 요청으로 구현한 운영 구조입니다. 승인 원고408편을 두 사이트에서 제공하고 미승인13편은 제외합니다. 실제 kr 연결 전에는 분야별 화면을 /knowledge/에서 제공합니다.

## 권장 방향

원고는 하나로 관리하고 독자가 들어오는 길을 두 가지로 둡니다. net은 국가를 출발점으로, kr은 분야를 출발점으로 삼습니다. 양쪽의 같은 글 페이지는 하나의 원본에서 생성하므로 수정·이미지 교체·출처 보완도 함께 반영됩니다. 같은 내용을 손으로 두 벌 복사하지 않습니다.

현재는 글마다 `proposed_domain` 하나만 부여해 두 사이트의 목록을 서로 배타적으로 생성합니다. 앞으로는 이 값을 대표주소를 정하는 정보와 목록에 노출할 정보를 나누어 사용해야 합니다. 메뉴에 링크만 추가하는 일과 두 사이트에 본문을 모두 제공하는 일은 범위가 다릅니다. 이 안은 후자도 지원하는 구상입니다.

## 독자가 보는 구조

| 사이트 | 첫 탐색 | 같은 글의 예 |
|---|---|---|
| knowledgewalk.net | 아시아대양주·유럽·아메리카·중동아프리카 → 국가 → 역사·도시·문화·생활 | 유럽 → 독일 → 문화 → 엘리제를 위하여 |
| knowledgewalk.kr | 분야 → 세부 분야 | 문화와 예술 → 음악 → 엘리제를 위하여 |

net의 기존19개 주요 국가와 기타 국가 방식은 유지합니다. 제거한 언어 분류도 되살리지 않습니다. 분야별 분류는 국가 분류를 대신하는 것이 아니라 함께 붙는 속성입니다.

kr에는 기존6개 대주제를 유지하면서 `역사와 도시`, `문화와 예술`을 추가하는8개 대주제 구성을 제안합니다. 음악은 문화와 예술 아래의 독립 서가로 두고 첫 화면의 빠른가기로도 바로 접근할 수 있습니다.

| 대주제 | 세부 분야 예 |
|---|---|
| 역사와 도시 | 정치와 제도·교역과 이동·전쟁과 전환·도시의 변화·고대 문명 |
| 문화와 예술 | 문학·음악·미술·건축·철학·영화·스포츠·신화와 민속 |
| 기업과 산업 | 기존 창업·경영·공장·유통·브랜드 |
| 컴퓨터와 디지털 | 기존 컴퓨터의 역사·소프트웨어·인터넷·데이터·AI·디지털 생활 |
| 돈과 금융 | 기존 화폐·은행·투자·보험·금융 기술 |
| 과학과 발견 | 기존 우주·생명·물질·측정·과학자의 발견 |
| 생활을 바꾼 물건과 기술 | 기존 식탁·옷·집·이동·놀이 |
| 생각과 지식 | 교육·기록과 지식 전달·사회 제도 등 기존 교양 콘텐츠 |

교차하는 글에는 둘 이상의 분야를 연결할 수 있습니다. 단, 같은 서가에 동일 원고 카드를 두 번 보여 주지는 않습니다. 특정 국가와 직접 관련 없는 복리·CRC 같은 글에 억지 국가를 부여하지 않습니다. 두 사이트 모두에서 전체 이야기·검색으로 읽을 수 있게 하고 net 국가 목록에는 관련 국가가 있는 글만 보여 줍니다.

## 두 사이트에 본문을 모두 제공할 때

한 글의 논리적 원본은 하나이며 양쪽 게시 페이지는 각각 생성합니다. 본문과 이미지·출처·번호 소제목·별도 바로가기는 같고, 국가/분야 경로와 추천 목록은 사이트 목적에 맞게 다를 수 있습니다. 문장을 억지로 바꾸어 서로 다른 글인 것처럼 만들 필요는 없습니다.

검색엔진에 대해서는 원고마다 대표주소를 하나 정하고 양쪽 페이지에 같은 canonical을 표시하는 구성을 권합니다. 기존 net 글은 기존 net 주소를, 기존 kr 글은 기존 주소 체계를 우선 유지해 불필요한 주소 변경을 줄입니다. 양쪽의 본문이 자동으로 검색에서 별개의 글로 인정되거나 두 배로 노출된다고 기대하지 않습니다. canonical은 검색엔진에 대한 선호 신호이며 최종 선택을 강제하는 보장은 아닙니다. 다른 쪽 페이지는 독자가 계속 읽을 수 있도록 제공할 수 있습니다.

현재 실제 kr 도메인은 `kr_live:false`이고 임시 주제 경로가 서비스 중입니다. 연결되지 않은 kr 주소를 갑자기 대표주소나 필수 이동 경로로 만들지 않습니다. 실제 kr 게시·HTTPS·이미지·검색을 확인한 뒤 도메인 전환과 기존 임시 주소의 안내를 처리해야 합니다.

## 원본과 게시 관리

원본JSON·이미지·출처는 현재 저장소의 동일 파일을 계속 사용합니다. 한 원고ID에 국가 목록, 분야 목록, 대표주소, 노출할 사이트를 별도로 기록하는 방향입니다. [샘플 메타데이터](../../config/proposals/shared-catalog-two-sites-20261107.json)는 활성 운영 기록입니다.

검토→승인의 편집 절차는 한 번만 거치며 두 빌드는 같은 승인 버전에서 생성합니다. 검토 원고는 어느 사이트에도 공개하지 않습니다. 두 호스팅 서비스의 배포는 별도 작업이므로 같은 원고 버전을 올리고 양쪽의 실제 응답을 확인하는 방식으로 맞춥니다. 게시 도중 한쪽이 실패하면 완료로 처리하지 않습니다.

이번10편 승인 후 논리적 공개 원고는408편입니다. 전체 공유를 적용하면 양쪽 서가에서 각각408편을 제공할 수 있지만 서로 다른 원고가816편으로 늘어나는 것은 아닙니다. 총421편 중 미승인13편은 계속 제외합니다.

## 구현에 필요한 변경과 검증

1.421개 원고의 기존 단일 배치와 원래 분야 정보를 바탕으로 공통 분류표를 작성하고, 국가 근거가 없는 항목은 빈값으로 유지합니다.
2.대표주소와 사이트별 노출 정보를 분리하고 기존 주소와 이전 링크를 보존합니다.
3.kr의 역사·문화 서가와 net의 전체 이야기·검색을 준비합니다. 중복 카드나 미승인 국가 노출을 방지합니다.
4.현재 `prepare()`의 도메인별 단일 선택을 공통 원고 선택으로 바꿉니다. 두 검색 목록이 서로 겹치면 안 된다는 기존 테스트도 새 요구에 맞게 바꿉니다.
5.승인 원고만 양쪽에 생성되는지, 본문/이미지 버전이 같은지, 원고별 canonical이 하나로 일치하는지, 기존 주소와 번호 바로가기·모바일 화면이 정상인지 확인합니다.
6.실제 kr 연결과 양쪽 배포를 검증한 뒤 새 탐색 구조로 전환합니다.

공유 게시 방식과 분야별8개 대주제를 적용했습니다. Hostinger 연결 검사42355887498은 종료코드2로 실패했고 실제 업로드는 실행하지 않았습니다. FTP 비밀번호 설정을 마친 뒤 실제 kr 도메인으로 전환합니다.
